## 决策表

### RAG 与检索

| 编号 | 决策 | 放弃的方案 | 理由 |
|---|---|---|---|
| D1 | 本地纯 Go 分块 + BM25 | 接 `memory` 类 MCP server 存书籍 | 通用记忆服务存的是摘要和实体，不存原文段落，无法做原文检索与定位 |
| D2 | 自研叙事图，不依赖 `codebase-memory-mcp` | 直接用 codebase-memory 索引小说 | 它的价值来自 tree-sitter 解析符号与调用边；小说没有 AST，属于范畴错误。只借鉴"把非结构化内容建成可查询图"的思路 |
| D3 | 向量存 BLOB + 暴力检索（暂不做） | `sqlite-vec` / `onnxruntime` | 项目锁定 Go 1.20 + `modernc.org/sqlite`（纯 Go），两者都要求 cgo |
| D4 | 先 BM25，embedding 后置 | 一上来就混合召回 | 单本书几百块，事实型查询（人名、术语、原句）BM25 更强；embedding 是唯一新增外部依赖 |
| D5 | 分块必须保留 `block_start/block_end` | 只存文本 | 引用不能回跳的 RAG 没有可信度 |
| D6 | 单字 + 二元组双份索引 | 只做 bigram | 只做 bigram 时单字查询（如"雨"）命中为 0，实测回归 |
| D7 | 索引只读本地缓存 | 重建索引时重新请求章节 | 避免触发下载限流与 `-2012/-2013` 风控 |

### 书架与有声书

| 编号 | 决策 | 放弃的方案 | 理由 |
|---|---|---|---|
| D8 | 分组双轨：cloud 镜像 + local 覆盖 | 单一来源 | 云端分组会在同步时覆盖用户在本地的整理 |
| D9 | 分组不回写云端 | 调用 `/shelf/archive` | 写接口频繁调用像自动化，与设备指纹约束冲突 |
| D10 | 有声书只做元数据展示 | 内嵌播放器 | `/audio/geturl`、`/track/text` 未验证；先探测再投入 |
| D11 | 不做本地 ASR | whisper.cpp 转写音频 | 需要 cgo，与纯 Go sqlite 的构建前提冲突 |
| D12 | 听书优先走电子书 TTS | 逆向有声书取流 | 覆盖所有已缓存正文的书，风险低；`/book/album` 已确认 `playTts` + 10 音色 |

### 叙事功能

| 编号 | 决策 | 放弃的方案 | 理由 |
|---|---|---|---|
| D13 | 平行世界 = 局部反事实 + 跳跃收敛 | 整本永久平行世界 | 150 幕串行生成要等 10–20 分钟，且误差累积到 20 幕后必然 OOC |
| D14 | 引力只拉"结果"不拉"路径" | 直接要求角色改变主意 | 直接改动机是最典型的 OOC；施力应优先用环境、第三方、信息泄露 |
| D15 | 引力按到期触发 | 每幕都强调"贴近原著" | 每幕提醒会让读者立刻察觉被操控 |
| D16 | 偏移过大时诚实退出 | 强行拉回主线 | 硬拉只会产出更差内容；承认"无法接回"是产品诚实 |
| D17 | memory.md 分区 + 引擎哈希 | 单一 Markdown 交给模型读 | AI 会"顺手优化"用户约束，几轮后宪法失效，是世界线腐化的头号原因 |
| D18 | 自由输入先做意图编译 | 直接把用户原话拼进提示词 | 不编译就会被忽略或越权，破坏世界观 |
| D19 | GitHub 只发分支不发原文 | 整章附带 | 版权；且分支包体积会失控 |
| D20 | 内容哈希锚定分叉点 | 依赖 WeRead `bookId` | 书 ID 是账号内标识，别人导入必然错位 |
| D21 | 远程分支当数据不当指令 | 关键词过滤 | 远程文本天然是 prompt injection 载体，必须结构性隔离 |
| D22 | 不做 AI 视频 | 生成分镜视频 | 跨镜头角色一致性几乎不可能，成本是图的 10–50 倍 |
| D23 | 插图按需生成 | 全量预生成 | 一本书 100–200 场景，全量 ¥20–60，用户可能只看 10 张 |

## 未决问题（需要产品决策）

| 编号 | 问题 | 影响 | 建议 |
|---|---|---|---|
| Q1 | 引力默认档位 | 决定"选择感"与"轨道感"的平衡 | 默认 `balance`（0.7），可调 |

## 推进顺序

```
故事图谱 → canon 锚点 + memory.md → 引力 → 自由输入 → GitHub 分发
```

不跳步的理由：锚点必须锚到具体场景的 block 区间，没有图谱，引力机制无处落脚。

当前建议的下一刀：**memory.md 的 schema、分区校验与规则校验器**。
理由是它不依赖图谱、可独立测试，且直接对冲"AI 改写用户规则"这个头号失败点。
