# 主题系统需求评估与补充说明

> 日期：2026-10-30
> 范围：软件 UI 主题（主目标）、阅读器视觉主题（可选扩展）、按钮与 UI 文本样式、主题管理与迁移
> 已确认口径（2026-10-30）：单色 = 纯色背景与单色系主题两者都做；渐变 = 线性 / 径向 / 锥形全部支持；接受“径向角度 = 内圈中心偏移方向”的定义；背景图允许网络 URL，下载后缓存到本地数据目录；主题默认不注入伪装皮肤；现有 6 套预设属于阅读器视觉，不能与软件 UI 主题混为一谈。
> 结论：现有实现只覆盖“阅读区纯色主题”的一部分；本轮新增的是软件 UI 主题，阅读器视觉主题作为独立分类保留并可选扩展。渐变、背景图、按钮定制、UI 文本定制、主题生命周期均需要新增模型与界面。

## 1. 结论摘要

### 1.1 现状

- 阅读区已有 6 套预设主题：纸白、羊皮、夜间、护眼、透明、等宽。这些是**阅读器视觉主题**，不是本轮要做的软件 UI 主题。
- 本轮主目标是**软件 UI 主题**：标题栏、侧栏、设置页、弹窗、按钮、UI 文本、窗口底色。
- 阅读器视觉主题可作为独立分类继续扩展，但必须与 UI 主题分开存储、分开选择、分开预览。
- 阅读区已支持字体、字号、行距、字距、段距、缩进、对齐、版心、页边距、分栏、行号、文字色、纸面色、标题色、强调色。
- 主题通过 `--r-*` CSS 变量作用于正文与纸面，切换主题不会重渲染正文。
- 应用外壳（标题栏、侧栏、设置页、按钮）使用固定的深色设计令牌，不随主题变化。
- 背景只支持“纯色字符串”或 `transparent`，没有渐变、图片的类型化模型和编辑界面。
- `customThemes` 字段已存在，但没有创建、改名、删除、排序、导入、导出的 API 和界面。
- 规格中的“主题导入/导出（JSON）”尚未实现。
- `surfaceOpacity` 字段存在，但前端没有实际使用。

## 2. 对原始需求的澄清

原始描述：“可选择单色，双色（径向类型，角度），自定义图片。可定制按钮，UI 文本样式。”

逐项拆解后，建议按下面的口径理解；其中带“待确认”的条目需要产品决策。

### 2.1 “单色”

存在两种合理解释：

1. **纯色背景**：背景使用一个颜色，无渐变、无图片。
2. **单色系主题**：整套配色围绕一个主色生成（背景、纸面、文字、强调色、按钮色），类似“墨蓝”“墨绿”“酒红”。

建议：已确认两者都做。背景类型里提供 `solid`（纯色）；UI 主题预设里提供若干“单色系”主题（整套外壳配色围绕一个主色生成）。

### 2.2 “双色（径向类型，角度）”

建议定义为：

- 双色 = 两个颜色停靠点（stop），可选一个中间位置比例。
- 渐变类型：`linear`（线性）、`radial`（径向）、`conic`（锥形），三种全部支持。
- 角度：`0–360°`，`0°` 指向上方，顺时针递增。
- 线性和锥形：角度直接决定渐变方向 / 起始边。
- 径向：CSS `radial-gradient()` 没有角度参数。角度用于把“内圈颜色中心”从几何中心沿该方向偏移，偏移量用 `0–100%` 表示；偏移为 0 时角度不产生视觉效果。实现时换算为 `radial-gradient(... at x% y%)`。
- 径向还需定义：形状（`circle` / `ellipse`）、范围（`closest-side` / `farthest-corner` / 自定义百分比）、中心点（默认 50% 50%）。

已确认采用“内圈中心偏移方向”的定义；偏移为 0 时角度不产生视觉效果，界面应禁用或隐藏角度控件。

### 2.3 “自定义图片”

需要明确：

- 来源：本地文件选择、拖拽、剪贴板粘贴、网络 URL（下载后缓存到本地数据目录）。
- 存储：本地文件复制到应用数据目录；网络 URL 先下载到缓存目录，再按同一套资源模型引用；不长期引用原路径或原 URL。
- 适配：`cover` / `contain` / `stretch` / `repeat`。
- 位置：九宫格或焦点坐标。
- 效果：不透明度、模糊、明暗、遮罩色与遮罩强度。
- 作用面：窗口背景、纸面、两者。
- 限制：格式、体积、尺寸、动图、EXIF 方向。

### 2.4 “可定制按钮”

需要明确：

- 范围：全部按钮，还是阅读工具栏 / 设置页 / 侧栏分别控制。
- 粒度：按按钮变体（主按钮、次按钮、幽灵按钮、图标按钮）统一配置，还是每个按钮单独配置。
- 可调项：圆角、高度、内边距、字号、字重、背景、文字色、边框、阴影、悬停/按下/禁用态、图标大小与间距。
- 是否跟随主题强调色。

建议：**按变体配置 + 全局密度**，不做逐按钮配置。逐按钮配置的维护成本和界面复杂度远高于收益。

### 2.5 “UI 文本样式”

需要明确：

- 范围：标题栏、侧栏导航、页面标题、正文说明、弱化文字、状态栏、提示气泡、按钮文字。
- 可调项：字体、字号、字重、行高、字距、颜色。
- 与阅读区排版的关系：完全独立，还是共用字体。
- 是否支持全局缩放。

建议：**独立于阅读排版**，按“角色令牌”配置，并提供 90% / 100% / 110% / 120% 的界面缩放。

## 3. 补充后的需求规格

### 3.1 主题分层模型（新增，P0）

将“主题”拆成三个作用域，避免一个 `Theme` 同时承担所有职责：

| 层 | 作用对象 | 主要内容 |
|---|---|---|
| `ui`（外壳） | 标题栏、侧栏、设置页、弹窗、通用控件 | 外壳配色、UI 文本、通用按钮、窗口底色 |
| `reader`（可选） | 正文、纸面、阅读工具栏 | 阅读排版、阅读配色、纸面背景、阅读区按钮 |
| `skin` | Word / VS Code / 微信等伪装皮肤 | 皮肤自身的结构色与覆盖规则 |

本轮默认交付 `ui` 主题；`reader` 主题保留为独立分类，作为可选扩展。

优先级从低到高：

1. 内置默认令牌
2. 用户 `chrome` / `reader` 主题
3. 皮肤结构样式
4. 用户在皮肤内显式开启的“应用主题配色”

规则：

- FR-THEME-00：本轮默认主题是 `ui` 主题；现有 6 套预设注册为 `reader` 主题，二者独立存储、独立选择、独立预览，不共用同一份列表。
- FR-THEME-01：阅读主题只影响阅读区，不得改变外壳。
- FR-THEME-02：UI 主题只影响外壳，不得改变正文排版或纸面。
- FR-THEME-03：伪装皮肤默认保持自身配色；提供“将配色应用到伪装皮肤”开关，默认关闭，避免破坏伪装效果。
- FR-THEME-04：皮肤开启配色应用时，只允许覆盖颜色类令牌，不允许覆盖布局、字号、间距和结构样式。
- FR-THEME-05：切换 UI 主题不得触发正文重新分页或重新渲染；切换阅读主题不得改变外壳。

### 3.2 背景系统（P0）

#### 3.2.1 类型

- FR-BG-01：支持 `solid`（纯色）、`gradient`（渐变）、`image`（图片）、`transparent`（透明）。
- FR-BG-02：`gradient` 支持双色，可选中间停靠点；`linear`、`radial`、`conic` 三种全部支持。
- FR-BG-03：角度范围 `0–360°`，`0°` 向上，顺时针；径向角度语义见 2.2。
- FR-BG-04：径向支持形状、范围、中心点、内圈偏移。
- FR-BG-05：UI 主题的窗口底色作用于外壳根节点；阅读主题的纸面背景作用于纸面；两者不共享同一字段。
- FR-BG-06：背景之上必须有可选的“可读性遮罩”（颜色 + 不透明度 0–80%），默认值需保证正文对比度。
- FR-BG-07：图片背景支持 `cover` / `contain` / `stretch` / `repeat`、九宫格位置、不透明度、模糊（0–24px）、明暗（50%–150%）。
- FR-BG-08：图片支持本地文件与 http/https URL。本地文件复制到数据目录；URL 由 Go 侧下载到数据目录缓存，记录 `assetId` 与来源 URL，不把 URL 直接交给渲染层。
- FR-BG-08A：URL 仅允许 http/https；限制 3 次重定向、15s 超时、15MB 上限；校验 Content-Type 与文件头；拒绝 GIF/SVG；失败时保留原背景并提示。
- FR-BG-08B：缓存键使用 URL 的 SHA-256；同一 URL 复用缓存；离线时直接使用缓存；提供“刷新缓存”。
- FR-BG-08C：URL 下载不得携带微信读书 Cookie/令牌；仅作为普通匿名图片请求。
- FR-BG-09：支持 PNG / JPEG / WebP；本地文件与 URL 下载统一解码、EXIF 纠正与缩放规则；单文件不超过 15MB；最长边超过 2560px 时自动等比缩小；默认拒绝 GIF 动图。
- FR-BG-10：解码失败时回退到纯色并提示；不得因单张背景图失败导致启动失败。
- FR-BG-11：图片资源按主题 ID 存放，删除主题时清理；启动时清理无引用资源。
- FR-BG-12：背景层级固定为：底色 → 渐变/图片 → 遮罩 → 纸面 → 正文。
- FR-BG-13：背景变化不得改变正文布局尺寸；分页只由排版参数决定。
- FR-BG-14：背景图切换时先预加载再应用，避免闪白。
- FR-BG-15：窗口背景为半透明或图片带透明度时，原生窗口背景必须同步为透明；否则保持不透明，避免四角透出桌面。

#### 3.2.2 可读性

- FR-BG-16：当正文与背景的对比度低于 4.5:1 时，界面显示警告，但不强制阻止保存。
- FR-BG-17：图片背景默认叠加一层与文字色相反的遮罩，强度可调。
- FR-BG-18：提供“一键提高可读性”：自动增加遮罩或加深/提亮背景。

### 3.3 按钮样式（P0 基础 / P1 完整）

- FR-BTN-01：按钮按变体配置：`primary`、`secondary`、`ghost`、`icon`。
- FR-BTN-02：可调令牌：圆角、高度、水平内边距、字号、字重、背景色、文字色、边框宽度/颜色、阴影、图标尺寸、图标与文字间距。
- FR-BTN-03：每个变体支持 `normal` / `hover` / `active` / `disabled` 四种状态；未单独设置的状态按规则派生。
- FR-BTN-04：默认“跟随强调色”，用户可关闭并手填颜色。
- FR-BTN-05：按钮样式作用于整个应用外壳与阅读工具栏；不做逐按钮覆盖。
- FR-BTN-06：提供全局密度：紧凑 / 标准 / 宽松，影响按钮高度与内边距。
- FR-BTN-07：图标按钮只允许调整尺寸、圆角、颜色与悬停背景，不允许改变图标本身。
- FR-BTN-08：按钮样式不得导致文字截断；最小高度与最小点击区域需满足 28×28px。

### 3.4 UI 文本样式（P1）

- FR-UITXT-01：按角色配置字体、字号、字重、行高、字距、颜色。
- FR-UITXT-02：角色至少包括：标题栏、侧栏导航、页面标题、区块标题、正文说明、弱化文字、状态文字、按钮文字、提示气泡。
- FR-UITXT-03：UI 字体与阅读字体独立；可一键“跟随阅读字体”。
- FR-UITXT-04：提供界面缩放 90% / 100% / 110% / 120%，作用于外壳，不影响阅读区字号。
- FR-UITXT-05：角色未单独设置时，从“基础文本”继承。
- FR-UITXT-06：不允许把字号设置到影响可读性的范围（建议 10–24px）。
- FR-UITXT-07：UI 文本换肤不得改变布局断点；超长文本仍需省略或换行。

### 3.5 预设主题（P0）

- FR-PRESET-01：现有 6 套（纸白、羊皮、夜间、护眼、透明、等宽）保留为**阅读器视觉主题**，不进入 UI 主题列表。
- FR-PRESET-02：新增独立的**软件 UI 主题**预设，至少包含 4 套单色系（墨蓝、墨绿、酒红、暖灰）与 2 套渐变示例；UI 主题不改变正文。
- FR-PRESET-03：UI 预设由“外壳配色 + 窗口底色/渐变/图片 + UI 文本 + 按钮”组成；阅读预设由“阅读配色 + 背景 + 排版”组成，两者不交叉组合。
- FR-PRESET-04：预设卡片按类型展示对应预览；UI 卡片展示标题栏、侧栏、按钮与文字样式，阅读卡片展示纸面、正文与字体。
- FR-PRESET-05：应用预设后仍可继续微调，微调结果进入“当前主题”，不自动覆盖预设。
- FR-PRESET-06：`ui` 与 `reader` 各自维护“当前主题”ID；切换 UI 主题不得修改 `reader` 的当前主题，反之亦然。

### 3.6 自定义主题生命周期（P1）

- FR-CUSTOM-01：支持新建、复制、重命名、删除、排序、设为当前。
- FR-CUSTOM-02：支持从当前状态“另存为主题”。
- FR-CUSTOM-03：主题名称唯一；重名时自动追加序号。
- FR-CUSTOM-04：删除当前主题时回退到默认主题，并二次确认。
- FR-CUSTOM-05：自定义主题数量上限建议 50，超出时提示。
- FR-CUSTOM-06：主题切换即时生效并自动保存；编辑过程防抖保存，避免频繁写盘。
- FR-CUSTOM-07：提供“恢复默认”与“撤销本次修改”；至少支持恢复到进入编辑页时的状态。
- FR-CUSTOM-08：导入/导出为单文件 JSON（扩展名建议 `.wrdtheme`），图片以 base64 内嵌，单文件上限 10MB。
- FR-CUSTOM-09：导入时校验 schema 版本、字段类型、颜色格式、资源大小；不合法时给出具体错误并拒绝导入。
- FR-CUSTOM-10：导出文件名使用主题名，去除非法路径字符。
- FR-CUSTOM-11：导入同名主题时提供“覆盖 / 新建副本 / 取消”。

### 3.7 皮肤与主题的交互（P0）

- FR-SKIN-01：皮肤继续负责结构、布局和仿真细节；主题只负责颜色与字体。
- FR-SKIN-02：默认不把用户配色注入伪装皮肤；新增开关“将主题配色应用到伪装皮肤”，默认关闭。
- FR-SKIN-03：开关开启后，仅覆盖皮肤的颜色令牌；皮肤的结构色（如微信绿、VS Code 状态栏）保持不变或提供单独开关。
- FR-SKIN-04：切换到伪装皮肤时，如果当前阅读主题会破坏伪装（例如高饱和背景图），界面需提示，但不强制切换。
- FR-SKIN-05：退出皮肤后恢复阅读主题原样。

```jsonc
    "base": { "fontFamily": "Segoe UI", "fontSize": 14, "lineHeight": 1.5, "weight": 400 }
  },
  "components": {
    "buttons": {
      "radius": 7,
      "density": "standard",
      "followAccent": true,
      "variants": {
        "primary": { "background": "#4d84ff", "text": "#ffffff" }
      }
    }
  }
}
```

兼容策略：

- 旧字段 `textColor`、`background`、`surface`、`fontSize` 等继续读取。
- 迁移时把旧 `Theme` 转成 `reader` 主题；UI 主题使用新增的默认值，不从旧 `Theme` 推导，避免把阅读器的纸面色误当成外壳色。
- `kind: "ui"` 时读取 `palette`（外壳令牌）、`background`（窗口底色）、`uiTypography`、`components`；`readerTypography` 忽略。
- `kind: "reader"` 时读取 `palette`、`background`（纸面）、`readerTypography`；`uiTypography` / `components` 忽略。
- 新增 `themeSchema` 字段；缺失时按 v1 处理。
- 迁移只做一次，写入 `settings.version`。

### 3.9 交互与界面（建议）

设置 → 外观，拆成 5 个页签，默认进入“界面主题”：

1. **界面主题**：UI 预设、窗口底色/渐变/图片、外壳配色、按钮、UI 文本、缩放。
2. **阅读器视觉**：现有 6 套阅读预设、阅读背景、纸面、阅读排版。
3. **主题库**：UI 与阅读两类自定义主题列表、导入/导出、新建/复制/删除。
4. **皮肤适配**：是否将配色应用到伪装皮肤、各皮肤的覆盖开关。
5. **高级**：主题 JSON 预览、恢复默认、清理未使用资源。

UI 主题与阅读器视觉必须使用不同的入口和预览，避免用户把“纸白”当成软件界面主题。

阅读器内的快捷面板保留：

- 预设色板；
- 背景类型快速切换（纯色 / 渐变 / 图片）；
- “更多外观设置”跳转到设置页；
- 当前主题名与“已修改”标记。

编辑器要求：

- 所有改动实时预览，不写盘直到防抖保存。
- 渐变编辑器提供可视化角度盘、两个色块、中心点拖拽。
- 图片编辑器提供裁切/焦点预览。
- 对比度警告就地显示。
- 关闭面板不丢弃已保存内容。

### 3.10 非功能需求

- FR-NFR-01：主题切换在 100ms 内完成视觉更新，正文不重新分页。
- FR-NFR-02：背景图导入在后台解码/缩放，界面不阻塞超过 200ms。
- FR-NFR-03：模糊半径上限 24px；超过时提示性能风险。
- FR-NFR-04：主题 JSON 中所有 CSS 值必须白名单校验，禁止注入 `url()`、`expression()`、`javascript:`。
- FR-NFR-05：图片路径必须限制在数据目录内，禁止 `..` 穿越。
- FR-NFR-06：主题资源不写入日志；导出文件不包含账号信息。
- FR-NFR-07：主题切换尊重 `prefers-reduced-motion`；默认不做渐变过渡动画。
- FR-NFR-08：正文对比度检查阈值 4.5:1；大字号可用 3:1。
- FR-NFR-09：所有新增字符串走现有中文文案；不引入 emoji 图标。
- FR-NFR-10：Go 侧主题结构变更需附带迁移单测；前端需通过 `tsc --noEmit`。

## 8. 一句话总结

当前应用已有“阅读区纯色主题 + 排版参数”的基础，但本轮需求的主体是**软件 UI 主题**：标题栏、侧栏、设置页、按钮、UI 文本与窗口底色，现有 6 套预设属于阅读器视觉，必须与 UI 主题分开。建议先建立 `ui` / `reader` 双分类与统一令牌，再实现窗口背景引擎（纯色/三种渐变/本地与 URL 图片）和组件定制，最后补主题管理与导入导出；伪装皮肤默认不注入主题配色，避免破坏伪装定位。
